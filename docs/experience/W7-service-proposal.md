# W7 服务实施方案

2026-10-21。范围按用户确认：本轮完成核心体验与验收；协作、评论、团队库、集中字体、插件运行只输出实施方案。本文是待立项设计，不代表服务已经提供，也不改变当前本地优先模式。

## 现有基础与边界

可复用 React/TypeScript 编辑器、文档模型、统一命令与校验、修订号、原子批量修改、本地库包和版本、字体检测／替换、MCP 权限与连接流程。现有 LoyoCloud 连接用于授权 AI 访问打开的编辑器；仓库中的云连接不提供服务端文件存储或多用户设计协作。浏览器本地库不等同于团队库；MCP 接入不等同于插件隔离运行环境。

优先在现有账号服务上增加团队与资源权限。身份服务的可扩展性、数据库和对象存储配额必须在服务端仓库核实后再确定部署参数；不以此前端仓库推断已具备能力。所有服务独立于 Penpot，禁止把 Penpot 服务作为产品后端。

## 目标架构

编辑器保留完整离线文件与导出。在线能力使用一个 BaizeFig 服务入口：身份和团队权限、文件与修订、协作会话、评论、库发布、字体资产；二进制资源放对象存储。先以模块化单体部署，协作长连接可独立进程运行，共用权限校验与审计；规模数据出现前不拆成大量微服务。

插件在浏览器沙箱中运行，通过受限消息协议访问统一命令接口。插件没有直接数据库、账号令牌、编辑器 DOM 或任意文件系统权限。部署仅服务在线能力，静态编辑器可单独分发。

## 数据与权限契约

| 实体 | 关键字段／约束 |
| --- | --- |
| Team / Membership | teamId、userId、owner/admin/editor/viewer；移除成员立即失去会话访问权 |
| Project / File | teamId、projectId、fileId、headRevision、schemaVersion、deletedAt；服务端每次读写检查权限 |
| Revision | revisionId、parent、author、commandBatch、resourceHashes、createdAt；不可变、可恢复、可导出 |
| Session / Presence | fileId、userId、clientId、baseRevision、expiresAt；光标／选区只做短期状态，不写文档历史 |
| CommentThread / Reply | fileId、pageId、nodeId 或文档坐标、author、body、resolvedAt、version；删除锚点后保留“原图层已删除”状态 |
| Library / Release | teamId、libraryId、releaseId、schemaVersion、contentHash、依赖清单；发布版本不可变，使用方显式升级 |
| FontAsset | family/style/weight、contentHash、许可证记录、可用团队、上传者；二进制读权限与团队权限一致 |
| PluginInstall / Grant | pluginId、version、manifestHash、publisher、capabilities、networkOrigins、状态；授权绑定版本和团队／用户 |

评论者只能写评论；查看者不能通过长连接、导出接口或插件绕过文件权限。编辑、评论、导出、库发布、字体管理和插件安装分别授权。分享链接有明确范围、到期时间和撤销能力；不默认公开。

## 协作与历史

第一阶段采用服务端排序的原子命令批次，复用现有命令校验。提交包含 fileId、clientId、requestId、baseRevision 和 commands；重复 requestId 返回原结果。服务端在同一事务内校验权限、基准修订、命令及资源引用，再写入新修订并广播。

跨修订命令必须定义冲突策略：不同节点的独立属性可重放；同一属性、删除与编辑、父子重排、组件传播和布局变更不静默覆盖。初版遇到不安全冲突返回冲突详情，让客户端保留本地草稿并选择重试／另存分支。确需无冲突离线合并时，再以真实命令样本评估 CRDT/OT；不能把整份 JSON 最后写入获胜称为多人协作。

撤销提交自己的逆向命令，而非恢复整份旧文档以覆盖其他人的修改。逆操作校验当前目标是否仍满足前提，不满足则提示冲突。断线重连先从 lastAckRevision 拉取增量；日志缺失则取快照；未确认请求用原 requestId 查询后重试。离线编辑仍可保存本地副本。

建议接口：GET /files/:id/snapshot、GET /files/:id/revisions?after=、POST /files/:id/commands、GET /files/:id/requests/:requestId、WS /files/:id/session。均为拟定契约，尚未上线。

## 评论体验

画布评论模式提供锚点、线程列表、回复、解决／重开和未读状态。原型预览与设计画布共享线程身份，使用不同坐标投影。创建、修改和解决均有服务端版本检查；作者可编辑本人回复，管理员按团队策略处理。通知初期使用应用内收件箱；邮件与外部通知另行确认渠道后实现。

验收覆盖不同账号的查看／评论／编辑、移动锚点图层、删层、撤销删层、权限撤销、离线回复重试、重复请求和线程同时解决。

## 团队库与字体

本地库包作为团队库版本格式基础，增加内容地址资源、依赖版本和发布权限。发布前校验组件、变体、覆盖、原始字形、图像、四类基础令牌和复合令牌引用。使用方固定 releaseId，展示更新差异，升级时保留实例覆盖；失败原子回滚。撤回版本禁止新引用，已有缓存文件继续打开，资源清理遵守引用保留规则。

字体上传先校验格式、大小、字体元数据和授权范围；服务端处理与预览任务隔离。按需下载并使用 FontFace 注册；失联或无权限时明确标记缺失字体，保留文档字体名和原始字形，禁止静默改成其他字体。集中字体不自动授予字体再分发权，导出嵌入按许可证策略控制。

## 插件生命周期

Manifest 明确 id、version、API version、入口、文件读写／导出权限和允许网络域。安装→校验签名／哈希→确认授权→启用→运行→终止→升级／撤销→卸载各有真实状态。升级增加权限时重新授权；卸载后撤销所有会话。沙箱设置执行时间、内存／消息大小和批次数限制。

只读 API 返回限定的文档快照；写 API 走统一命令、预览校验、expectedRevision 与幂等键，一次批次形成一条撤销。插件错误／超时不会破坏文档；权限撤销立即中断网络代理及文档访问。先支持少量自有插件验证契约，再开放第三方发布。

## 实施顺序与完成门槛

| 阶段 | 交付 | 必须通过 |
| --- | --- | --- |
| S0 身份／文件底座 | 服务端仓库审计、团队角色、文件快照、资源存储、备份恢复 | 两个不同账号＋匿名访问，跨团队越权拒绝，恢复演练 |
| S1 协作 | 命令日志、长连接、重连、幂等、冲突与个人撤销 | 两人并发、删改冲突、100 次断线重试无重复、权限中途撤销 |
| S2 评论 | 锚点线程、回复、解决、未读 | 多角色权限、锚点删除／恢复、重复提交与并发解决 |
| S3 库／字体 | 不可变发布、升级与回滚、受控字体获取 | 覆盖保留、复合令牌模式、跨文件资源、离线缓存、字体缺失 |
| S4 插件 | 沙箱、能力协议、安装升级撤销与卸载 | 越权／超时／网络阻断、批次撤销、版本授权变更 |

上线前建立单文件人数／节点数／批次速率的容量目标，再记录 P50/P95 延迟、断线恢复时间、服务内存及存储成本。未有真实基准前不承诺并发人数或机器配置。每阶段具备功能开关与回滚；回滚不删除用户文件、评论、版本和本地草稿。

## 后续立项需要确定的内容

服务端仓库及其维护入口、团队角色与访客政策、文件存储区域与保留周期、目标并发容量、字体授权政策、插件发布与审核规则。以上是下一阶段的产品和部署决策，本轮不创建账号、发送邀请、发布服务或接入第三方通知。
